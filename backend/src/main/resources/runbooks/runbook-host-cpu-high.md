# 主机 CPU 持续高负载处置 SOP

## 适用范围与目标

适用于节点 CPU 使用率持续超过策略阈值、load average 异常或业务延迟同步升高。目标是区分真实计算压力、单进程失控、I/O 等待和监控误报，并在不扩大故障面的前提下恢复容量。

## 只读取证

1. 在监控中确认持续时间、影响节点、CPU 核数、user/system/iowait/steal 分布以及同集群基线。
2. 通过 `uptime`、`top -b -n 1`、`ps -eo pid,ppid,comm,%cpu,%mem --sort=-%cpu` 确认负载来源。
3. 检查最近发布、定时任务、容器限额、节点驱逐和云主机 steal time；保留时间戳、进程 PID、工作负载和指标截图。
4. 若 system 占比高，检查中断、连接数和内核日志；若 iowait 高，转入磁盘或存储链路排查。

## 判断与处置

- 单业务进程异常：先联系服务负责人确认流量和发布，再采用扩容、限流或摘流。重启、终止进程属于有状态动作，必须审批并保留回滚路径。
- 多业务共同升高：检查节点是否超售或容量不足，优先调度新实例到健康节点；禁止直接修改全局调度策略。
- steal 异常：收集宿主机证据并升级云平台；不要在原因未明时反复重启虚机。
- 监控误报：对照节点本地指标和另一数据源，修复采集链路，不以关闭告警代替修复。

## 恢复验证与升级

连续两个告警窗口确认 CPU、load、错误率和延迟恢复，业务实例无新增重启，变更记录可追溯。P0/P1、关键节点全部受影响、15 分钟内无下降趋势或需要强制终止进程时，立即升级值班负责人和服务 owner。

## 安全边界

禁止未审批执行 kill、reboot、清缓存、批量驱逐或永久降低告警阈值。任何写操作必须先说明影响范围、回滚命令和验证指标。
