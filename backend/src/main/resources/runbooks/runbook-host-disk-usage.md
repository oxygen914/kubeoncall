# 主机磁盘空间不足处置 SOP

## 适用范围与目标

适用于文件系统使用率持续升高、写入失败或 Kubernetes DiskPressure。目标是定位增长目录和责任服务，优先采用可审计的保留策略释放空间，避免误删业务数据。

## 只读取证

1. 使用 `df -hT` 确认挂载点、文件系统类型和剩余空间，使用 `df -i` 排除 inode 耗尽。
2. 在目标挂载点内用 `du -x -d 2` 定位大目录；检查已删除但仍被进程占用的文件 `lsof +L1`。
3. 核对日志、容器镜像、临时文件、core dump、数据库/WAL 和对象缓存的保留策略及最近增长速率。
4. 记录大文件路径、owner、大小、mtime 和对应进程，禁止跨挂载点扫描造成额外负载。

## 判断与处置

- 日志异常增长：联系服务 owner 修复日志级别或循环错误；仅按既定日志轮转策略压缩/清理。
- 容器镜像与临时层：确认镜像未被运行实例引用后，使用平台标准垃圾回收；禁止直接删除容器运行时目录。
- 已删除文件占用：评估进程重载或滚动重启，需审批并验证服务副本。
- 数据库、WAL、备份文件：交由数据 owner 按产品流程处理，禁止值班人员直接删除。

## 恢复验证与升级

确认可用空间回到容量红线之上、增长率恢复正常、写入与节点状态正常，并建立后续容量工单。剩余空间不足 5%、根分区受影响、无法识别文件 owner 或需要删除业务数据时立即升级。

## 安全边界

禁止未审批执行 `rm -rf`、截断未知文件、删除数据库/WAL、清理运行时目录或扩大文件系统。任何删除必须列出精确路径、owner、保留依据和恢复方式。
