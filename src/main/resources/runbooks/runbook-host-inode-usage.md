# 主机 inode 耗尽处置 SOP

## 适用范围与目标

适用于磁盘容量仍充足但无法创建文件、inode 使用率超过阈值或节点 DiskPressure。目标是识别海量小文件来源并按数据生命周期安全治理。

## 只读取证

1. 使用 `df -i` 确认 inode 耗尽的挂载点，结合 `df -hT` 排除容量告警。
2. 在同一挂载点逐层统计目录项数量，例如 `find <path> -xdev -type f | wc -l`；限制范围，避免从根目录全盘扫描。
3. 检查临时目录、日志切片、邮件队列、容器层、应用缓存和失败任务输出，记录文件 owner、mtime 分布及生成速率。
4. 关联最近发布、任务重试和清理作业失败记录。

## 判断与处置

- 临时/缓存文件：仅按服务已声明的 TTL 和清理流程执行，先抽样确认文件可再生。
- 日志碎片：修复轮转配置和异常写入源，再按保留策略批次清理。
- 容器运行时目录：通过标准镜像/容器垃圾回收处理，不直接进入数据目录删除。
- 业务文件：由数据 owner 确认生命周期、备份和恢复验证后处理。

## 恢复验证与升级

确认 inode 使用率回落到红线以下、新文件创建成功、生成速率稳定且清理任务恢复。根分区 inode 超过 95%、服务已写入失败、扫描显著影响 I/O 或文件归属不明时立即升级。

## 安全边界

禁止使用未经限定路径的批量 find/delete，禁止按文件名猜测用途，禁止直接删除数据库、队列或容器运行时文件。写操作必须先审批、小批次执行并可停止。
