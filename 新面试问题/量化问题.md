# 量化问题

## 一、KubeOnCall（Multi-Agent 智能运维）量化追问

### 1. 你在简历里写“系统目前已在实验室环境稳定运行，纳管 5 台物理/容器节点，成功拦截/自动化处理日常运维请求 100 余次”，这几个数字分别是怎么统计出来的？
**连续追问：**
1. 这 100 余次里，什么算一次“请求”？是用户主动问答、告警触发、审批恢复，还是三者都算？
2. “成功拦截”和“自动化处理”是不是两类不同口径？你有没有分别统计？
3. 这 100 余次里，有多少是纯问答类、多少是告警类、多少进入了工具调用？
4. 这 5 台节点里，物理机和容器节点各几台？如果节点规模只有 5 台，这个系统的复杂度是否做重了？
5. 这些统计数据是来自数据库、Redis、审计日志，还是你自己手工整理的？
6. 你怎么证明这 100 余次不是把大量低价值重复请求也算进去了？
7. 有没有“自动化处理发起了，但最后失败或回滚”的情况？这种算不算成功？

### 2. 你说“切实大幅降低了人工排查负担”，这个收益你是怎么量化的？
**连续追问：**
1. 你有没有统计过上线前后，平均一次故障排查耗时分别是多少？
2. 如果没有严格 A/B，对“负担降低”这个结论你是怎么得出来的？
3. 你衡量的是平均排障时长、人工接管次数，还是首次定位时间？
4. 对实验室这种低并发内部场景，你怎么证明不是“样本太少，结论不稳”？
5. 有没有记录“用户采纳率”或“建议被执行率”？
6. 如果面试官质疑这只是主观感受，不是量化收益，你怎么自证？

### 3. 你说 Workflow/DAG 能实现告警触发后的固化排障流水线，这条链路的命中率和完成率你怎么测？
**连续追问：**
1. 你定义的“命中”是指告警被成功路由到某条 workflow，还是 workflow 最终产出有效结论？
2. 你定义的“完成”是所有节点都成功，还是允许部分节点降级后也算完成？
3. 你有没有统计过每个节点的成功率、超时率、降级率？
4. 哪个节点最容易失败？是日志取数、状态比对、RAG 检索，还是结果推送？
5. 如果同一个告警触发多次，你是按事件数算完成率，还是按去重后的故障实例算？
6. 有没有做过“开启 DAG”与“纯人工排查”之间的处理耗时对比？

### 4. 你说“状态机 + 幂等”防止告警抖动导致重复执行，这个去重效果是怎么验证的？
**连续追问：**
1. 你有没有构造过告警抖动压测，模拟同一告警短时间重复上报几十次？
2. 幂等拦截率怎么统计？是 `SETNX` 成功/失败次数，还是业务任务实际创建数？
3. 你怎么验证不会“误杀”真正的新一轮故障？
4. 有没有记录“重复告警进入前”和“进入后”的任务数差异？
5. TTL 的长短是拍脑袋定的，还是基于历史告警间隔统计出来的？
6. 如果去重效果你只在线上观察过，没有系统实验，你会怎么诚实回答？

### 5. 你说节点级做了“超时干预与失败降级策略”，你是怎么量化这个策略有效的？
**连续追问：**
1. 你有没有统计超时前后的平均链路 RT 变化？
2. 降级后你怎么衡量“系统可用性提高了”，是完成率提高、还是长尾 RT 降低？
3. 你有没有看过 P95 / P99，而不只是平均响应时间？
4. 哪些节点最需要超时保护？它们的阈值是怎么定的？
5. 如果一个节点经常超时，是不是说明它本身设计就有问题，而不是靠降级掩盖？
6. 你有没有对比过“不开降级”和“开降级”的实际差异？

### 6. 你说多智能体链路里单个 Agent 采用 ReAct 循环“取证→校验→调整”，这个循环效果你怎么量化？
**连续追问：**
1. 你有没有统计平均每次请求会循环多少轮？
2. 最多循环几轮，这个阈值是基于什么数据定的？
3. 你怎么证明多轮循环带来的收益大于额外延迟？
4. 有没有分析过“1 轮就够”“2~3 轮收益最大”“4 轮以后开始跑偏”这类分布？
5. 你记录的是 thought/action/observation 全量轨迹，还是摘要指标？
6. 如果面试官问你：ReAct 让成功率提升了多少，你拿什么回答？

### 7. 你说 Verifier + HITL 可以拦截高危动作，这个“拦截能力”是怎么测出来的？
**连续追问：**
1. 你有没有自己构造一批危险指令样本，比如重启、删配置、清理目录，去做拦截测试？
2. 你的评估指标是什么？召回率、误杀率、人工通过率，还是别的？
3. 有没有出现过本来应该拦却没拦的 case？你是怎么发现的？
4. 如果误杀正常动作太多，会不会严重影响用户体验？你怎么平衡？
5. 你说“高危动作强依赖审批唤醒”，那审批平均等待时间有没有统计？
6. 如果面试官追问“你怎么证明 HITL 不是形式主义”，你拿什么数据说服？

### 8. 你说 RAG 采用“问题改写 → 混合检索 → 重排序”，那你的 RAG 召回率是怎么测出来的？
**连续追问：**
1. 你的评测集是怎么来的？是人工整理问答对，还是从真实告警/用户问题里抽样？
2. 你评的是 recall@k、MRR、NDCG，还是只看主观效果？
3. 如果是实验室内部知识库，样本量有多少才足够说明问题？
4. 评测时是按“是否召回到正确子块”算，还是按“是否最终命中正确父块”算？
5. 如果一个问题本来就能被 BM25 命中，那向量召回的收益怎么单独看出来？
6. 你有没有区分解释类问题和实体精确匹配类问题分别评估？

### 9. 你说前置 Query Rewrite 以后检索效果更好，这个提升是怎么量化的？
**连续追问：**
1. 你有没有做“原问题直接检索”和“Rewrite 后检索”的对照实验？
2. 你说改写后收益更高，那提升指标具体是 recall@k 还是最终回答可用率？
3. 你怎么防止 Rewrite 把告警码、IP、Pod 名这些精确 token 改坏？
4. 对哪类问题收益最大？解释类、模糊问法，还是缩写很多的问题？
5. 有没有哪类问题改写后反而变差？你怎么处理？
6. 如果面试官问你“Rewrite 真正提升了多少”，你准备怎么回答？

### 10. 你说“专有名词以及垂直领域名词召回提升 40%”，这个 40% 是怎么测出来的？
**连续追问：**
1. 这 40% 提升的分母是什么？是 recall@10、top1 命中率，还是某类问题集合的命中率？
2. 你是和哪一个 baseline 比较得出的？纯向量、纯 BM25，还是不做 metadata / rewrite 的旧版本？
3. 这个测试集里的“专有名词/垂直名词”是怎么定义和筛选的？
4. 样本规模多大？如果只有十几个例子，这个 40% 统计意义够吗？
5. 你有没有做过人工复核，防止“看起来像命中、其实不相关”？
6. 如果面试官继续追问“这是绝对提升 40 个点，还是相对提升 40%”，你怎么解释清楚？

### 11. 你说 Parent-Child 分块、Metadata 过滤、BM25+向量、RRF、Cross-Encoder 都做了，那每一层的收益你是怎么拆开测的？
**连续追问：**
1. 你有没有做过消融实验（ablation study）？
2. 如果做过，最先带来明显收益的是哪一层？
3. 如果没做过，你怎么证明不是“把流行词堆满”？
4. Cross-Encoder 带来的效果提升和延迟成本分别是多少？
5. 如果线上 RT 压力大，你最先砍哪一层，有数据支撑吗？
6. 如果只能保留两层，你留什么，理由是什么？

### 12. 你说 BM25 是为了兜底特殊告警码、IP、容器名强命中，那这个“兜底效果”怎么验证？
**连续追问：**
1. 你有没有专门构造过包含告警码、IP、Pod 名、容器名的问题集？
2. 在这些问题上，纯向量检索和混合检索的差距具体有多大？
3. 你怎么判断 BM25 命中的文档是真有帮助，而不是只做了关键词碰撞？
4. 如果 BM25 已经很强，那向量检索在你这个场景里究竟补了什么？
5. 这个混合检索设计在小规模实验室文档库里是否值得？你如何量化“值得”？

### 13. 你说解释类走 RAG、查设备指标走 planner，这个路由的准确率是怎么测的？
**连续追问：**
1. 你的路由评估集怎么构造？
2. 路由错误时最常见的错分是哪类？
3. 你有没有统计过路由准确率、回退率、双路兜底命中率？
4. 混合型问题，比如“为什么 CPU 高，顺便看最近 10 分钟负载”，你怎么评估是否路由正确？
5. 如果路由错了，最终影响是答非所问还是错误调工具？你有量化吗？
6. 你怎么证明这个路由不是过早优化，而是真的必要？

### 14. 你说工具调用能力覆盖设备、告警、配置、知识库等跨域场景，那工具调用成功率和有效率是怎么统计的？
**连续追问：**
1. 你记录的是工具调用总次数、成功次数、超时次数，还是更细的错误类型？
2. 成功率是“HTTP 返回 200”就算成功，还是必须返回对决策有用的信息？
3. 你怎么统计“低价值循环”，比如连续几次查日志但没新增证据？
4. 不同工具的成功率是否分开统计？哪个最不稳定？
5. 你有没有做过工具级 SLA 或健康度面板？
6. 如果模型反复误调用某个工具，你怎么从数据上发现？

### 15. 你说这个系统不是 demo，而是能落地的 Agent 系统，那你拿什么量化指标证明“不是 demo”？
**连续追问：**
1. 你最想展示的 3 个核心指标是什么？
2. 这些指标是线上真实数据，还是离线测试数据？
3. 你有没有统计人工接管率、审批命中率、拒答率、重规划率？
4. 如果这些指标目前还没做全，你最先补哪几个？为什么？
5. 面试官如果说“5 台机器、100 次请求不足以证明工程价值”，你怎么回应？

## 二、智图（智能遥感图片协同工作系统）量化追问

### 16. 你说系统解决了实验室非结构化科研产出管理散乱、跨端协同困难的问题，这个“解决效果”你怎么量化？
**连续追问：**
1. 你有没有统计上线前后，找图时间、重复上传次数、协同冲突次数这些指标？
2. 如果没有严格前后对照，你是通过什么证据判断系统确实改善了问题？
3. 这个系统当前实际多少人用？高峰时多少人同时在线？
4. 如果只有十几个人用，这些收益是不是容易被质疑样本太小？
5. 你怎么证明不是“功能做出来了，但大家其实没怎么用”？

### 17. 你说支持 GB 级图片分块上传，那你的 chunk size 和并发分片数是怎么定出来的？
**连续追问：**
1. 是通过压测得出的，还是工程经验值？
2. 你测试时的文件大小、网络环境、浏览器环境分别是什么？
3. 你为什么最后选 8MB~16MB、3~5 并发这种量级，而不是更小或更大？
4. 你有没有对比不同 chunk size 下的失败重传成本和整体耗时？
5. 你关注的核心指标是吞吐、稳定性，还是失败恢复效率？
6. 如果面试官问你“这个参数到底怎么来的”，你怎么用数据说话？

### 18. 你说分块上传和断点续传让大图上传更稳定，这个“更稳定”是怎么测的？
**连续追问：**
1. 你有没有统计上传成功率、平均上传时长、重试次数、断点续传命中率？
2. 有没有做过网络抖动、页面刷新、断线重连这些异常场景测试？
3. 如果一个 1GB 文件在弱网环境下上传，你怎么定义“成功”和“可接受”？
4. 你有没有对比过“不开断点续传”和“开断点续传”的差异？
5. 如果断点续传命中率很低，是不是说明状态机设计没真正发挥价值？

### 19. 你说秒传基于 MD5 指纹校验，这个秒传命中率和收益是怎么统计的？
**连续追问：**
1. 你有没有统计过重复文件上传占比？
2. 秒传命中后，平均节省多少上传时间和存储空间？
3. 你怎么判断秒传命中的文件确实应该复用，而不是误判？
4. 有没有出现过“同名不同内容”或者误命中的边界 case？
5. 如果实验室本身重复上传不多，秒传这个能力值不值得？你怎么量化？

### 20. 你说预签名 URL 允许前端直传 MinIO，从而减少应用层压力，这个效果怎么量化？
**连续追问：**
1. 你有没有对比过“经过应用服务器转发”和“直传对象存储”两种方案的接口 RT 和服务器负载？
2. 你的应用层节省了多少带宽、CPU、内存占用？
3. 预签名 URL 的有效期是怎么定的？有没有测试过过长或过短带来的问题？
4. 你有没有统计 URL 过期重签率、上传失败率？
5. 如果面试官问“你怎么证明直传真的必要”，你拿什么数据回答？

### 21. 你说 Redis 状态机实现跨会话断点续传，这个状态机的可靠性怎么验证？
**连续追问：**
1. 你有没有模拟客户端中途断线、刷新页面、重新登录后继续上传？
2. 你怎么统计状态恢复成功率？
3. 如果分片重复上传、乱序上传、部分丢失，最终恢复率怎么测？
4. Redis key 的 TTL 是怎么定的？你有观察过过期导致的续传失败吗？
5. 如果状态恢复依赖人工验证，没有自动测试，你会怎么诚实回答？

### 22. 你说 Kafka 异步化处理大图片解析和 ES 建索引，这条链路的吞吐和时延是怎么测的？
**连续追问：**
1. 你有没有统计上传完成到索引可搜索之间的平均时延和 P95？
2. Kafka 主要缓解的是 HTTP 超时，还是削峰填谷？这个你怎么证明？
3. 消费失败重试率、DLQ 命中率有没有统计？
4. 你怎么区分慢是慢在 AI 脚本、索引构建，还是消息堆积？
5. 如果用户刚上传完在列表能看见、搜索搜不到，这个一致性窗口你有多大把握控制？

### 23. 你说 MySQL 与 Elasticsearch 通过事务消息保障最终一致，这个“一致性效果”怎么验证？
**连续追问：**
1. 你有没有统计过 MySQL 已有记录但 ES 暂未建索引的窗口比例？
2. 有没有做过一致性巡检，比如抽样比对 MySQL 主数据和 ES 索引？
3. 如果消费失败重放，怎么防止旧消息覆盖新状态？你有没有用版本号或更新时间做验证？
4. 进入 DLQ 的消息最终补偿成功率是多少？
5. 如果没有做完整巡检机制，你怎么证明“最终一致”不是口头说法？

### 24. 你说 Edit Lock + 心跳续期能防脏写，这个防脏写效果怎么量化？
**连续追问：**
1. 你有没有统计过锁冲突次数、锁抢占次数、锁超时释放次数？
2. 上线前后，多人同时编辑导致的脏写冲突减少了多少？
3. 心跳丢失场景下，你怎么统计误释放率和锁悬挂率？
4. 你的锁 TTL 和心跳间隔是怎么定的？有压测或日志依据吗？
5. 如果面试官问“你怎么证明这个锁方案比版本号方案更适合当前场景”，你怎么回答？

### 25. 你说 WebSocket 保证了协同实时性，那这个“实时性”是怎么测出来的？
**连续追问：**
1. 你测的是消息端到端延迟、广播延迟，还是页面可见更新延迟？
2. 测试环境是什么？是同局域网、同实验室网络，还是跨网络？
3. 高峰时同时在线多少连接？消息延迟是否明显抖动？
4. 你有没有统计握手失败率、重连次数、异常断开率？
5. 如果面试官追问“实时性是否只是主观感觉”，你怎么用指标回答？

### 26. 你说 JWT + Redis 让权限变更秒级生效，这个“秒级”是怎么测出来的？
**连续追问：**
1. 你有没有做过权限收回后立即再请求的测试？
2. 你测的是平均生效时延，还是最坏生效时延？
3. Redis 更新到请求拦截之间有没有一致性窗口？
4. 你有没有统计过因为缓存/续签导致的短时越权 case？
5. 如果面试官继续追问“你凭什么说秒级，不是几十秒”，你怎么证明？

### 27. 你说 ThreadLocal + 拦截器透传租户上下文，这种设计的稳定性怎么验证？
**连续追问：**
1. 你有没有构造并发请求、线程池复用场景去验证是否串租户？
2. 你怎么检测 ThreadLocal 没清理干净的问题？
3. 有没有压测或单元测试专门覆盖 `finally remove` 这类逻辑？
4. 如果没有线上事故，你怎么证明它是安全的，而不是“暂时没出事”？
5. 面试官如果问“你有没有见过串租户的真实坏案例”，你怎么回答？

### 28. 你说 Agent 图片处理引擎能自主编排“影像预处理 → 特征提取 → VLM 解译 → 研报生成”，那这个 Agent 的效果怎么量化？
**连续追问：**
1. 你有没有统计过自动处理成功率、人工接管率、平均处理时长？
2. 你怎么定义“成功处理”？是流程跑通，还是报告真正可用？
3. 你有没有比较过固定脚本流水线和 Agent 动态编排的差异？
4. 工具误调用率、参数错误率、空结果率有没有统计？
5. 如果面试官问“这个 Agent 不是花架子吗”，你拿什么指标证明它真有价值？

### 29. 你说把 eo-learn 的 EOTask 封成原子工具给大模型调度，那工具选择正确率怎么测？
**连续追问：**
1. 你有没有构造过一批标准任务，去评估模型是否会正确选择 NDVI、云检测等工具？
2. 你怎么定义“选对工具”？是领域专家判断，还是按预期链路比对？
3. 如果模型选错工具，后续结果污染率有没有统计？
4. 你有没有看过不同 prompt 或 description 下的选工具差异？
5. 如果没有严格离线评测，你怎么避免把“偶尔成功”说成稳定能力？

### 30. 你在简历里如果写“前端调用 LLM 首 token 响应在 40ms 以内”，那这个 40ms 你是怎么测出来的？
**连续追问：**
1. 你测的是浏览器发请求到收到首字节，还是服务端转发到模型返回首 token？
2. 你有没有把前端网络延迟、后端排队时间、模型本身推理时间拆开看？
3. 测试是在本地环境、实验室内网，还是接近真实线上环境？
4. 样本数量有多少？平均值、P95、P99 分别是多少？
5. 如果你只是偶尔看到一次 40ms 峰值很低的结果，为什么敢写到简历里？
6. 面试官如果质疑这个数字过于理想化，你怎么自证？

## 三、通用量化追问（两个项目都能打）

### 31. 你简历里所有“提升 XX%”“降低 XXms”“成功率达到 XX%”这种数字，分别是怎么测出来的？
**连续追问：**
1. 你的 baseline 是什么版本、什么配置、什么数据集？
2. 你的样本量有多大？是否有统计波动？
3. 你看的到底是平均值，还是 P95 / P99？
4. 测试环境和实际运行环境一致吗？
5. 这些数字是一次实验结果，还是长期观测结果？
6. 如果没有完整实验平台，你是怎么尽量把数据做得可信的？

### 32. 你做这些量化时，数据来自哪里？日志、埋点、链路追踪、数据库，还是手工记录？
**连续追问：**
1. 你有没有统一的指标口径，避免前后统计方式不一致？
2. 如果是手工统计，你怎么避免样本偏差？
3. 如果是日志统计，你如何保证日志本身没漏打、没重复？
4. 有没有区分线上真实数据和离线测试数据？
5. 面试官如果追问“你这个数字可复现吗”，你怎么回答？

### 33. 如果面试官继续施压：你这些量化结果是不是“挑最好看的数据写上去”的，你怎么回应？
**连续追问：**
1. 你会不会主动说明哪些数据是工程观测值、哪些是严格对照实验值？
2. 如果某个数字统计意义没那么强，你会怎么诚实表达而不显得心虚？
3. 你怎么区分“趋势明确”和“精确结论成立”这两种说法？
4. 如果没有特别漂亮的数据，你会拿什么替代来证明项目价值？
5. 你觉得面试官最容易怀疑你哪类量化表述？为什么？
