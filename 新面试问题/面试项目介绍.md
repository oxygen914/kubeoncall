
## 1. KubeOnCall 项目介绍
 KubeOnCall 是一个实验室内部用的智能运维助手，主要目标不是做特别重的平台化建设，而是想解决实验室同学日常维护服务器时，遇到环境问题、告警问题、排障问题比较分散、比较依赖熟手经验的情况。这个项目本质上是一个 Spring Boot 后端，我把知识库检索、工具调用、多 Agent 编排和告警工作流放到了一起。对于日常问答类问题，它会走 Planner、Verifier、Executor 这条链路，先规划再执行再校验；对于告警类问题，会走另一套相对固定的 Workflow/DAG 流程，把日志取数、状态比对、知识检索和结果推送串起来。

这个项目规模其实不大，就是实验室内部场景，纳管节点也不多，主要价值不是高并发，而是把重复性的运维问题收敛下来，减少人工排查成本。我在里面重点做了三块：第一块是多 Agent 的排障执行链路；第二块是基于 Redis 的状态保存和审批暂停恢复，避免高风险动作直接落地；第三块是面向实验室知识库的 RAG 检索，包括 Query Rewrite、混合检索和重排序这些能力。整体上它更像一个偏工程落地的智能运维小系统，而不是一个对标企业级的大平台。

## 2. 智图项目介绍
实验室里做的一个智能遥感图片协同系统，主要是为了解决实验室非结构化科研图片资料管理很乱、文件很大、多人协作不方便的问题。因为我们这边很多遥感图一张就有 550M 到 1G 左右，直接用普通文件管理方式体验很差，所以我重点围绕“大图上传、可靠存储、协同编辑、智能处理”这几个点做了设计。后端是 Spring Boot，存储这块用了 MinIO，检索用了 Elasticsearch，上传链路做了分块上传、断点续传和秒传，尽量让大文件在弱网或者中断场景下也能继续传。

这个项目的用户规模其实不大，主要就是实验室十几个人内部使用，所以它不是那种高并发平台，而是一个很强调实用性的内部系统。我自己觉得比较有代表性的点有三块：第一块是用 Redis 状态机去记录上传进度，配合预签名 URL 做前端直传 MinIO；第二块是多人在线标注时，用 WebSocket 加 Edit Lock 来防脏写；第三块是把一些遥感图像处理脚本和 eo-learn 的任务封成 Agent 可调度的工具，让系统在图片上传后可以自动做预处理、特征提取、视觉解译和研报归档。整体来说，它是一个学生项目，但确实比较贴近实验室内部真实使用场景，而不是单纯为了演示做出来的 demo。
