# 阿里云百炼模型联调

Docker profile 使用以下模型，不在仓库保存 API Key：

| 能力 | 默认模型 | 接口 |
| --- | --- | --- |
| Embedding | `text-embedding-v4`（1536 维） | OpenAI 兼容 `/compatible-mode/v1/embeddings` |
| Rerank | `qwen3-rerank` | 原生 `/api/v1/services/rerank/text-rerank/text-rerank` |
| 记忆结构化提取 LLM（可选） | `qwen-plus` | OpenAI 兼容 `/compatible-mode/v1/chat/completions` |

运行真实探针前，将本地密钥导入环境变量。下面的命令仅从工作区的私有密钥文件读取，不会把密钥写入 Git：

```bash
export ALIYUN_API_KEY="$(sed -n 's/^ali-api-key-cao:[[:space:]]*//p' ../api-key.md | head -n 1)"
./scripts/verify-aliyun-models.sh
```

探针依次验证鉴权、Embedding 向量维度、Rerank `output.results` 协议和 LLM Chat Completions 协议。应用层会在 Embedding 维度与配置不一致时拒绝该向量并回退到词法检索；RAG 响应的 diagnostics 会保留相应回退原因。

2026-07-16 本机真实验收结果：

- `text-embedding-v4` 返回 1536 维向量；应用级查询使用 `elasticsearch_knn`，`vectorFallback=false`。
- `qwen3-rerank` 返回两个有效分数；应用级查询为 `crossEncoderApplied=true`、`rerankStrategy=cross_encoder`。
- `qwen-plus` Chat Completions 鉴权和消息协议成功。
- 500ms 慢响应故障注入被标记为 `TimeoutError`，rerank 降级为 `retrieval_order_fallback`。
- 1536 维配置收到 2 维向量时，diagnostics 记录 `expected=1536, actual=2` 并回退词法检索。

真实成功路径和故障注入路径均经过 KubeOnCall 的 `/api/knowledge/query`，不只是独立 curl 探针。

启动 Docker 环境时可按需启用记忆 LLM 提取：

```bash
export MEMORY_LLM_EXTRACTION_ENABLED=true
docker compose --profile alerting up -d
```

若探针返回 `401`，API Key 未被当前百炼地域/业务空间接受，或该密钥没有模型访问权限；应在百炼控制台创建/授权可访问对应模型的 API Key，不能通过改写客户端请求绕过。
