## 1. 验收范围

本次验证覆盖：

1. 使用仓库外凭据启动真实 Planner 模型。
2. 启动期模型 canary、错误 Key 失败关闭和模型能力状态。
3. `/api/v1/executions` 持久化 Ask 全链路。
4. Loki 与 Prometheus 统一 Evidence 采集和 MySQL 持久化。
5. Planner、Evidence、Conclusion、异步任务和工作流节点的关联。
6. 临时联调令牌自动清理。

本次不覆盖：

- Kubernetes Tool Adapter 的正式部署。
- Kubernetes Events、current/previous Pod logs 和资源状态的真实适配器联调。
- 版本化 SOP、告警、变更事件和拓扑证据联调。
- Pending、CrashLoopBackOff、OOMKilled、Node 不可用故障注入。
- 真实变更、审批恢复、验证超时、自动回滚和人工升级演练。
- 生产可用性、成本、容量和多节点高可用验收。

- 仓库中的 `.env.example`、Compose 和 Spring 配置只包含变量引用和非敏感默认值。
- 未把 Key、Authorization Header、完整模型请求或完整日志写入本验收记录。

## 5. 统一证据结果

| Evidence 类型 | 来源 | 状态 | 说明 |
| --- | --- | --- | --- |
| `POD_LOG` | Loki | `SUCCEEDED` | 使用服务端构造的固定范围查询，返回已脱敏、受长度限制的日志片段 |
| `METRIC` | Prometheus | `SUCCEEDED` | 使用既有固定 PromQL 监控摘要，不接受用户或模型提交任意 PromQL |
| `ALERT` | `alerts.getActiveAlerts` | `UNAVAILABLE` | 当前外部事实源未接通 |
| `SOP` | `knowledge.searchSop` | `UNAVAILABLE` | 当前版本化 SOP 事实源未接通 |
| `RESOURCE_STATE` | Kubernetes/CMDB/Topology | `UNAVAILABLE` | Kubernetes Tool Adapter、CMDB 和拓扑事实源未接通 |

Prometheus 当前指标没有 `environment` 标签。采集器先检查数据源的范围能力，在数据源不支持
环境筛选时保留 cluster/namespace 约束并省略 environment matcher，同时持久化
`environmentFilterApplied=false`，避免把“标签能力缺失”误判为“无数据”。

直接 Prometheus 证据成功后，系统会移除同一逻辑证据槽中失败的
`prometheus.queryRange` Planner 占位项，避免重复展示和重复置信度扣分。

## 6. 结论可信度解释

最终结论保持 `PARTIALLY_SUPPORTED / LOW`，没有被标记为 `RESOLVED`。低分原因可解释：

- 请求没有精确资源 UID，`targetCertainty=0`。
- 当前没有 Kubernetes 资源状态或 Events 直接证据，`directEvidence=0`。
- SOP、告警、CMDB 和拓扑来源不可用，缺失信号惩罚达到当前上限。
- Loki 与 Prometheus 两个来源成功，因此能给出受限的只读观察，但不足以证明根因或恢复。

该结果证明当前实现能够区分“工作流执行成功”和“结论证据充分”，不会因 HTTP 200 或模型回答
成功而伪造已解决状态。
